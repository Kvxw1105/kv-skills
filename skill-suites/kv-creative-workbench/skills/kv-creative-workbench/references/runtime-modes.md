# Runtime modes

## Spark

Use when the user wants fresh angles, names, or reframed questions. Run Frame and Diverge only. Deliver breadth without feasibility scoring.

## Standard

Use for a meaningful but bounded decision. Run Frame, Diverge, Converge, and Validate only when the goal is commercial. Usually finish with two or three candidates.

## Deep creative

Use when conventional ideation has failed or the user explicitly asks for a stronger creative leap. Run a high-intensity divergent pass, then a calm de-dramatization pass, blind convergence, and validation. Preserve strange mechanisms; remove decorative excess.

## Review

Use when the user supplies a candidate list. Skip new ideation unless the list is homogeneous or a core gap appears.

## Decision

Use when the user needs a choice among mature options. Prioritize convergence, validated tradeoffs, and a direct recommendation.

## Repair

Use when an existing concept or plan has failed. Identify the failed assumption and route to its owning stage. Do not restart the entire workflow.

## Quick

Use when speed matters. Process at most three candidates and perform only one downstream validation pass. State major assumptions.
