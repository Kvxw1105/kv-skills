# Framing methods

Use four to six methods, selected for the problem.

## Naming reconstruction

Move the concept into a different category. Test names from systems, rituals, training, marketplaces, games, diagnostics, companions, infrastructure, or environments. The new name must imply a different mechanism.

## Actor reconstruction

Replace the default actor:

- user with payer;
- individual with group;
- expert with novice;
- creator with audience;
- operator with beneficiary;
- human with institution or environment.

## Goal reconstruction

Replace the stated goal with the underlying job:

- learn -> reduce uncertainty, build confidence, rehearse identity, pass a threshold;
- create -> gain proof, coordinate collaborators, accumulate reusable assets;
- improve efficiency -> remove decisions, reduce switching, prevent rework.

## Boundary reconstruction

Change scale, duration, location, frequency, or required effort. Test ten users versus one million, one minute versus one year, one-off versus ritual, local versus networked, synchronous versus asynchronous.

## Medium reconstruction

Remove the assumed interface. Ask what happens without an app, text, screen, AI, expert, or live interaction. Then test the opposite extreme.

## Opposite reconstruction

Invert the goal or constraint. Ask whether slowness, friction, failure, secrecy, public commitment, or deliberate limitation could create value.

## Language-game reconstruction

Place the same term inside different rule systems: school, workplace, therapy, sport, market, religion, game, laboratory, court, or community. Extract the changed incentives and actions, not only vocabulary.

## Evidence reconstruction

Ask what observable behavior would prove the problem exists. Reframe around repeated workarounds, payments, avoidance, complaints, or coordination failure.
