# Transformation patterns

## Reduce form

App -> manual service -> report -> template -> prompt -> checklist -> prototype.

Use when full development is not required to validate the mechanism.

## Narrow actor

Mass audience -> one profession -> one workflow -> one high-pain moment.

Use when the concept is too broad to communicate, acquire, or test.

## Split user and payer

Beneficiary -> sponsor, employer, parent, institution, or client.

Use when use value exists but payment control differs.

## Convert automation to decision support

Full replacement -> draft, ranking, warning, recommendation, or review layer.

Use when reliability, regulation, or trust makes automation too risky.

## Convert product to content system

Tool -> recurring analysis, public benchmark, case library, or educational series.

Use when distribution and authority should precede product development.

## Convert one-off work to asset

Service -> reusable rubric, dataset, workflow, template, or skill.

Use when repeated delivery reveals stable structure.

## Remove dependency

Proprietary data -> user-provided data, public data, manual intake, or synthetic prototype.

Use when access blocks testing.

## Change time scale

Continuous platform -> periodic review, event-triggered intervention, or one critical moment.

Use when retention assumptions are weak.
