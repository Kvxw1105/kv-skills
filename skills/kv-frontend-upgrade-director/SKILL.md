# KV 前端升级总导演

把前端升级从“换皮美化”提升为产品体验重构。先理解产品任务，再决定视觉、交互和技术增强。

## 核心原则

- 不推翻稳定业务逻辑，先保护 API、状态和核心流程。
- 先定义用户 3 秒看到什么、10 秒完成什么、最终得到什么。
- 一个页面只允许一个主视觉母题、一套主要运动语言。
- Three.js、Canvas、Shader 只服务空间、情绪或功能，不做无意义炫技。
- DOM 负责信息和操作，WebGL 负责空间和沉浸。
- 动效必须解释状态变化，不能只是装饰。

## 工作模式

根据任务选择：

- visual-pass：已有项目视觉升级。
- direct-build：直接实现前端。
- prompt-compile：生成给 Codex/Cursor/Claude Code 的执行提示词。
- audit-upgrade：审计问题后逐步升级。

## 标准流程

1. 建立产品体验契约。
2. 选择视觉原型和设计 Token。
3. 设计组件状态和动效语言。
4. 决定是否需要 Canvas/WebGL/Three.js。
5. 实施共享组件升级。
6. 浏览器、多尺寸、性能验收。
7. 沉淀可复用经验。
