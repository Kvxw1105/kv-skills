# 经验进化与版本治理

## 三级结构

1. **Candidate**：一次实战中出现，尚未证明可迁移；
2. **Validated**：在至少两个不同场景有效，边界和收益清楚；
3. **Promoted**：成为稳定 Skill 规则、模式或脚本。

## 候选记录字段

- 场景和用户任务；
- 原问题与失败表现；
- 解决机制；
- 证据和测试；
- 可迁移范围；
- 性能/复杂度成本；
- 失败边界和降级；
- 私密性与许可；
- 当前状态。

## 晋升门

同时满足：真实项目使用、可迁移、收益明确、无私人依赖、失败边界清楚、没有更简单成熟方案、至少一次回归验证。

## 防膨胀

- 不把单次审美偏好晋升为原则；
- 不重复记录已有模式；
- 新规则优先替换或合并旧规则；
- SKILL.md 保持薄控制层，细节进入 references；
- 私人项目经验保存在项目 `.agent/` 或私人扩展，不进入公开版。

## 版本记录

每次发布记录：新增模式、修正规则、脚本变化、兼容性、已验证案例、未解决风险。重大路由变化升 minor，破坏性行为升 major。
