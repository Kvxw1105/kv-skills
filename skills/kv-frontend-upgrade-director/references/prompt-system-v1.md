# KV 前端视觉与交互升级提示词系统 v1.0

> 一套面向已有网站、Web 应用、H5、工具页、官网、工作台与管理后台的可热插拔前端升级提示词。
>
> 核心目标：在不破坏现有业务能力的前提下，提高视觉识别、交互手感、空间层次、信息秩序、响应式质量、性能可靠性与完成度。
>
> 适用对象：Codex、Claude Code、Cursor Agent、GPT 编程 Agent、Kimi、灵光、Trae、Windsurf，以及具备读写项目能力的本地 Agent。

---

## 0. 这套提示词解决什么问题

很多 AI 前端项目的问题不在于“不会写代码”，而在于缺少统一判断：

- 页面看起来能用，却像通用 AI 模板；
- 加了 Three.js、粒子和光效，仍然没有高级感；
- 视觉升级以后破坏了业务、路由、表单或状态；
- 动画很多，却无法解释产品正在发生什么；
- 桌面端截图不错，手机端拥挤、溢出、裁切；
- 高级效果依赖 CDN，一断网就白屏；
- Agent 声称“已完成、已验证”，实际上没有跑浏览器；
- 页面每一个局部都做了美化，整体仍然没有主角。

这套系统采用一条更稳的路线：

> **先保护业务，再建立视觉命题；先把产品状态空间化，再决定动效和 Three.js 画什么；先让页面结构成立，再用视觉奇观强化记忆。**

它可以作为：

1. 新项目的前端总提示词；
2. 已有项目的增量视觉升级模块；
3. 某个页面的 Three.js/动效强化模块；
4. UI/UX 质量审查与修复提示词；
5. 交给弱模型的分阶段执行包；
6. 未来沉淀为 Skill 的母稿。

# 第一部分：使用方法

## 1.1 三种使用方式

### 方式 A：整包总控

适合：

- 新项目从零构建；
- 已有项目需要整体升级；
- Agent 能读取代码、运行项目、打开浏览器并修改多文件；
- 你希望 Agent 自己完成审计、设计、实现、验证和交付。

使用：复制“第二部分：最完整总控提示词”。

### 方式 B：按模块热插拔

适合：

- 页面结构已经稳定，只想提升审美；
- 只想加入语义动效；
- 只想升级 Three.js 主视觉；
- 只想修移动端、性能或细节；
- 不希望 Agent 重新理解整个项目。

使用：从“第三部分：可拆分模块”选择一到三个模块，追加到原开发提示词后。

### 方式 C：分轮执行

适合：

- 模型能力有限；
- 项目较大；
- 一轮同时做业务、视觉、动效容易跑偏；
- 需要保护已有功能。

推荐顺序：

1. 审计与冻结；
2. 视觉命题与设计系统；
3. 核心页面示范；
4. 动效与空间层；
5. 响应式与性能；
6. 浏览器验收与修复。

## 1.2 热插拔输入变量

在使用提示词之前，尽量替换以下变量。信息不足时可以保留占位符，让 Agent 先从代码与页面中推断，再明确标记推断项。

```yaml
PROJECT_NAME: 项目名称
PROJECT_PATH: 本地项目路径或仓库地址
PROJECT_TYPE: 官网 / SaaS / 工具 / 工作台 / 管理后台 / H5 / 内容站 / 其他
PRIMARY_USER: 核心用户
PRIMARY_JOB: 用户进入后最重要的任务
CORE_ROUTE: 最重要的页面或流程
CURRENT_STACK: React/Vue/Svelte/HTML/Next.js/Vite/其他
CURRENT_STYLE: 当前视觉风格
TARGET_FEELING: 希望产生的情绪与气质
BRAND_ASSETS: Logo、IP、字体、色彩、图像或已有品牌语言
MUST_KEEP: 必须保留的功能、文件、路由、接口和数据
DO_NOT_TOUCH: 禁止修改的模块、数据库、鉴权、配置或未提交文件
PERFORMANCE_TARGET: 设备、帧率、加载时间或体积目标
DELIVERY: 源码 / 单文件预览 / 构建包 / PR / 提示词
```

---

## 1.3 默认执行原则

无论使用哪个模块，都建议在前面追加以下保护头：

```text
这是一个已有项目的非破坏式升级任务。

先读取真实代码、路由、状态、数据流和现有功能，再决定改动。保留数据库、API、鉴权、权限、核心业务状态、现有路由和用户数据。除非明确要求，不要为了视觉重构业务逻辑，不要替换技术栈，不要删除已有功能，不要重写无关文件。

先列出：
1. 已观察到的现状；
2. 计划保留的稳定能力；
3. 本轮只修改的范围；
4. 可能风险；
5. 可验证的验收标准。

修改完成后必须运行项目并进行浏览器实测。未实际运行的内容标记为“未验证”，不得写成“已完成”。
```

# 第二部分：最完整总控提示词

下面这份可以整段复制给具备工程能力的 Agent。

```text
你现在是本项目的“前端视觉与交互升级总工程师”。你的任务要越过简单换色、加圆角和堆粒子的表面处理，在不破坏现有业务能力的前提下，把项目升级成具有明确视觉命题、成熟交互手感、稳定响应式、可靠降级与独特品牌识别的正式产品。

【项目输入】
- 项目名称：{{PROJECT_NAME}}
- 项目路径/仓库：{{PROJECT_PATH}}
- 项目类型：{{PROJECT_TYPE}}
- 核心用户：{{PRIMARY_USER}}
- 用户最重要的任务：{{PRIMARY_JOB}}
- 核心页面/流程：{{CORE_ROUTE}}
- 当前技术栈：{{CURRENT_STACK}}
- 当前视觉：{{CURRENT_STYLE}}
- 目标气质：{{TARGET_FEELING}}
- 品牌资产：{{BRAND_ASSETS}}
- 必须保留：{{MUST_KEEP}}
- 禁止改动：{{DO_NOT_TOUCH}}
- 性能目标：{{PERFORMANCE_TARGET}}
- 交付形式：{{DELIVERY}}

一、先保护现有产品

1. 读取真实项目结构、路由、主要组件、状态管理、API、数据模型、鉴权、构建命令和现有测试。
2. 先运行现有项目，确认基线是否可用。记录现有错误，避免把旧问题误判为本轮回归。
3. 建立功能冻结清单：哪些功能、路径、数据和交互必须原样保留。
4. 若工作区存在用户未提交文件，不得擅自恢复、删除、覆盖、暂存或提交。
5. 不要为了追求视觉统一，把高频工具页做成低效率艺术展；前台可以更有情绪，后台以信息效率和可操作性为优先。

二、建立体验内核

用一句话定义：
- 用户 3 秒内首先看到什么；
- 10 秒内能完成什么核心动作；
- 1 至 3 分钟内能得到什么可观察结果。

区分：
- 核心动作；
- 辅助功能；
- 纯装饰。

任何视觉效果都必须至少服务于以下一种目的：
- 建立品牌记忆；
- 解释产品状态；
- 引导用户下一步；
- 强化操作反馈；
- 帮助理解复杂信息；
- 建立空间层级。

三、先定义视觉命题，再写 CSS

按照以下公式写出一句视觉命题：

“{{核心情绪}} + {{材质/媒介}} + {{核心形状}} + {{动态特征}} + {{克制原则}}”

示例：
“低照度东方神性 + 墨金纸片 + 残缺浑天仪 + 缓慢蓄力、瞬时锻造 + 大面积暗部与单一主光源。”

随后将抽象词转成可实现参数：
- 高级：低色数、稳定层级、精确留白、克制阴影、清晰对比；
- 炫酷：一个主动态效果、强暗部、局部高亮、有限速度；
- 科技：数据关系、状态反馈、空间秩序，不等于蓝紫霓虹；
- 东方：结构、留白、材质、光源和节奏，不等于堆龙纹、祥云和古风装饰；
- 可爱：形状、弹性、声音和触控反馈，不等于贴纸堆叠。

页面最多保留：
- 一个主视觉焦点；
- 一个主要动效语言；
- 两级强调色；
- 一套统一材质逻辑。

禁止默认使用：
- 通用紫蓝渐变；
- 所有卡片玻璃拟态；
- 同尺寸圆角矩形铺满页面；
- 无业务意义的发光球、网格和粒子宇宙；
- 每个元素都带辉光；
- 图标、标题、按钮同时争夺注意力；
- 低对比灰字冒充高级。

四、建立设计令牌

把颜色、字号、字重、间距、圆角、边框、阴影、层级和动画曲线集中为语义化 Token。不要在组件里散落大量魔法数字。

至少定义：
- background / surface / elevated / overlay；
- text-primary / text-secondary / text-muted；
- accent-primary / accent-secondary / danger / success；
- border-subtle / border-strong；
- space scale；
- typography scale；
- motion duration；
- motion easing；
- z-index layer；
- responsive content width。

暗色和浅色必须分别校准，禁止简单反色。

五、建立视觉层级

缩成 25% 缩略图时，仍应一眼看出：
1. 页面主角；
2. 主要动作；
3. 当前状态；
4. 内容阅读顺序。

通过明暗、大小、位置、留白和运动速度建立层级。次要信息主动后退。不要让所有边框、文字、阴影和动效处于同一强度。

六、DOM 与空间渲染分层

普通文字、表单、按钮、导航、菜单、表格和可访问内容继续使用语义 HTML/DOM。

Three.js、Canvas、SVG 或视频只承担：
- 空间；
- 情绪；
- 复杂可视化；
- 品牌主视觉；
- 状态的空间化表达。

不要把整个产品界面画进 Canvas。WebGL 层默认 pointer-events: none；需要拾取时，只为明确交互对象启用 Raycaster。

推荐层级：
1. WebGL/Canvas 场景；
2. 暗角、颗粒、雾、扫描线等气氛后处理；
3. 正常 DOM 内容与控件；
4. Toast、临时过渡元素、命令面板等即时反馈。

七、先把产品状态空间化，再决定 Three.js 画什么

禁止先制作一个炫酷 3D 场景，再把产品文案贴上去。

先列出产品核心状态，例如：
- 空闲；
- 输入；
- 分析；
- 生成；
- 等待；
- 成功；
- 失败；
- 可编辑结果。

为每个状态定义：
- 画面发生什么变化；
- 用户能感知到什么；
- 哪个参数被驱动；
- 动画从哪里开始、到哪里结束；
- 状态能否撤回或重复；
- 失败时怎样恢复。

建立统一状态对象，至少区分：
- 业务状态；
- 动画临时状态；
- 用户输入；
- 全局设置；
- 渲染状态；
- 异步锁；
- 降级状态。

八、语义动效

动画必须解释状态变化。

为每个核心操作定义反馈矩阵：
- 点击：轻压缩或亮度变化，80-160ms；
- 选择：颜色、边框、位移或局部聚焦；
- 加载：持续但低干扰的运动；
- 成功：聚合、上扬、释放或收束；
- 失败：短促边框、低音或轻微位移，不羞辱用户；
- 撤回：沿原路径回收，不瞬间消失；
- 结果：分层出现，支持截图与继续操作。

元素必须有来源与去向。必要时使用跨媒介接力：DOM 元素先移动到空间目标，WebGL 对象再接续运动，让用户感知为同一对象完成转换。

所有运动使用平滑插值、阻尼或时间轴，避免直接跳值。对帧率敏感的动画应使用 deltaTime，保证 60Hz、120Hz 和低帧率设备上的速度一致。

九、Three.js 与 GPU 规则

只有当 3D 能承担空间、情绪或功能时才引入 Three.js。

可选技术：
- PerspectiveCamera；
- InstancedMesh；
- BufferGeometry；
- ShaderMaterial；
- RenderTarget；
- Raycaster；
- Points / GPU 粒子；
- CanvasTexture；
- 轻量后处理；
- GSAP 或自定义时间轴。

性能规则：
- 控制 devicePixelRatio 上限；
- 重复物体使用 InstancedMesh；
- 合并几何与材质；
- 避免每帧创建对象；
- 避免在动画循环中频繁查询 DOM；
- 移动端减少粒子、细分、灯光和后处理；
- 页面不可见时暂停或降低动画；
- 支持 prefers-reduced-motion；
- 给出无 WebGL、外部资源失败和低性能设备的降级方案。

材质规则：
- 禁止满屏 Bloom；
- 高亮只服务核心对象；
- 用 Fresnel、透明度、线框、局部自发光和光晕建立层次；
- 一个主对象可以由实体、线框和光晕多层组合；
- 通过材质层次提升体积感，不依赖无限增加模型数量。

十、响应式采用结构重排

按内容空间切换布局：
- spacious：宽屏多区；
- compact：紧凑双区；
- portrait：竖屏单列；
- scroll-safe：矮屏或极窄屏安全滚动。

要求：
- 页面级使用 Grid/Flex；
- 组件内部可用 Container Query；
- Grid/Flex 子项设置 min-width: 0 / min-height: 0；
- 使用 clamp、minmax、auto-fit；
- 触控目标不低于 40px，核心按钮接近 44-48px；
- 达到可读与触控下限后禁止继续缩小；
- 降级顺序：减外边距 → 减装饰间距 → 缩小非核心文字 → 换行 → 重排 → 隐藏说明/装饰 → 开启安全滚动；
- 不使用 transform: scale() 整体缩小页面；
- 不用 overflow:hidden 掩盖核心内容溢出。

移动端应重新组织视觉焦点、场景位置、信息顺序与控制密度，并降低 GPU 压力。

十一、声音与触觉

声音默认关闭或克制开启。首次用户手势后再创建 AudioContext。

为不同阶段定义不同音高、音色、时长与包络。避免长音、刺耳音和高并发。无音频素材时，可以用 Web Audio API 合成短音，但要设置起音和衰减，防止数字爆音。

声音、触觉只做增强层，不能承担唯一关键信息。必须提供关闭方式。

十二、真实产品界面必须成立

若这是工具、SaaS 或工作台：
- 真实产品组件承担主要叙事；
- 主视觉最终要自然收束到可操作界面；
- 高级感不能牺牲信息密度和效率；
- 加载、空状态、错误、完成、禁用、撤回、重复提交都要处理；
- 按钮不能是空壳；
- 结果必须能继续编辑、保存、导出或进入下一步。

十三、外部依赖与降级

外部 Three.js、字体、图片、模型、音频和 API 可能失败。

要求：
- 远程资源有超时和失败回退；
- 关键体验不因单个资源失败而白屏；
- Three.js 失败时可切换 Canvas 2D、SVG、视频或静态海报；
- 降级版本保留核心状态、核心操作和品牌母题；
- 错误对用户可理解，对开发者可追踪；
- 不在前端写入密钥。

十四、浏览器实测

完成代码后实际运行项目，至少检查：
- 首次进入；
- 核心成功路径；
- 输入为空或失败路径；
- 快速重复点击；
- 完成后再次执行；
- 移动端 390×844；
- 桌面端 1366×768 或 1440×900；
- 一个矮屏横屏；
- 键盘焦点；
- prefers-reduced-motion；
- 外部资源失败；
- scrollWidth <= clientWidth；
- 控制台错误；
- 动画是否造成布局跳动；
- 页面不可见或低性能时的负载。

问题标记为：
- observed：直接观察；
- reproduced：稳定复现；
- inferred：推测风险；
- existing：原有问题；
- regression：本轮引入；
- fixed_verified：修复并复测通过。

十五、交付要求

最终返回：
1. 设计判断与视觉命题；
2. 保留了什么；
3. 修改了什么；
4. 核心实现机制；
5. 实际测试范围；
6. 已验证结果；
7. 未验证与剩余风险；
8. 源码、预览、构建或 PR；
9. 下一轮最值得做的三项升级。

不要用“看起来应该没问题”冒充测试结果。不要仅提供截图，必须提供真实可交互产物或可运行代码。
```

# 第三部分：可拆分热插拔模块

以下模块可以独立使用。建议一次插入一至三个，不要让弱模型同时重构所有层级。

---

## 模块 01：已有项目非破坏式升级

### 适用

已有网站或应用功能基本可用，只想升级外观与体验。

### 提示词

```text
对当前项目执行非破坏式前端升级。

先读取真实代码和运行现状，建立功能冻结清单。必须保留数据库、API、鉴权、权限、路由、数据模型、核心业务状态与已有用户流程。不要替换技术栈，不要重写无关业务，不要删除功能，不要覆盖用户未提交文件。

本轮只允许修改：视觉系统、布局层级、组件表现、交互反馈、动效、响应式和前端性能。若发现业务问题，记录为独立事项，不在本轮擅自改动。

实施顺序：
1. 运行现有项目并记录基线；
2. 列出 must_keep 与 do_not_touch；
3. 选择一个核心页面做示范；
4. 提取共享设计令牌与组件规则；
5. 扩展到相邻页面；
6. 浏览器回归核心路径。

验收：功能无回归、路由可达、表单可用、核心状态完整、手机无严重溢出、控制台无新增错误。
```

## 模块 02：视觉命题与反模板化

### 适用

页面整洁但平庸，像普通 AI SaaS、模板站或组件库拼装。

### 提示词

```text
不要先换颜色和加装饰。先为项目写出一句视觉命题：
“情绪 + 材质/媒介 + 核心形状 + 动态特征 + 克制原则”。

把抽象要求转换成参数，并提出一套独特但可执行的视觉语言。页面只能有一个主焦点、一个主要动效语言、两级强调色和一套统一材质逻辑。

主动消除：紫蓝渐变、满屏玻璃卡、同尺寸圆角矩形、无意义光球粒子、低对比灰字、所有元素发光、模板化 Bento 堆叠。

要求即使关闭背景动效，页面仍然依靠排版、明暗、留白、形状和信息结构成立。缩成 25% 缩略图后，仍能辨认主角、主操作和阅读顺序。

先输出视觉命题、色彩比例、形状语法、材质、动效节奏和反例，再实现代码。
```

---

## 模块 03：设计令牌与细节统一

### 适用

页面局部细节还可以，整体不统一，颜色、边框、圆角、阴影和间距互相打架。

### 提示词

```text
为当前项目建立语义化 Design Token，并用它统一现有页面。

至少覆盖：背景层级、表面层级、正文/辅助/禁用文字、强调/成功/危险色、弱/强边框、字号阶梯、字重、间距阶梯、圆角、阴影、模糊、动效时长、缓动曲线、z-index、最大内容宽度。

禁止在组件中继续散落无规律魔法数字。不要机械把所有组件改成同一个圆角、阴影和边框强度。核心区域稳定，辅助区域后退，浮层与结果层有明确层级。

暗色和浅色分别校准，不做简单反色。完成后检查 Button、Input、Select、Tabs、Table、Modal、Toast、Tooltip 的 hover/active/focus/disabled/loading/error/success 状态。
```

---

## 模块 04：信息层级与排版升级

### 适用

页面“什么都有”，但没有重点，阅读顺序混乱。

### 提示词

```text
重新建立页面视觉权重，不改变业务信息。

用明暗、字号、字重、位置、留白和运动速度区分：
1. 页面主角；
2. 核心操作；
3. 当前状态；
4. 主要内容；
5. 辅助说明；
6. 元数据。

次要元素主动降低对比，不让所有边框和图标同样清晰。避免只靠放大字体建立层级。控制行长、段落密度和数字可读性。

在 25% 缩略图、黑白模式和关闭背景动效三种情况下验收层级是否仍成立。
```

## 模块 05：产品状态空间化

### 适用

想做独特动态视觉，又不想得到与产品无关的粒子背景。

### 提示词

```text
先列出产品的核心状态和状态转换，再设计视觉空间。

状态至少考虑：空闲、输入、分析/处理、等待、成功、失败、结果可编辑、撤回/重试。

为每个状态定义：
- 空间对象；
- 位置、形态、材质或光线变化；
- 动画来源和去向；
- 用户能否立即理解；
- 对应的业务变量；
- 是否可中断、重复或回滚。

Three.js、Canvas 或 SVG 中的每个主对象必须映射到真实产品概念。禁止制作一个漂亮但与业务无关的背景，然后把产品文案贴上去。

最后输出“业务状态 → 视觉参数”的映射表，并在代码中使用统一状态对象驱动 DOM、声音和空间渲染。
```

## 模块 06：语义动效与状态机

### 适用

页面动画多但散，或者交互显得生硬、廉价。

### 提示词

```text
把动画升级成语义动效系统。

为点击、选择、输入、加载、成功、失败、撤回、结果和重复执行建立反馈矩阵。动画必须解释状态变化，元素有来源和去向。

建立集中状态对象，区分：业务状态、动画临时状态、用户输入、异步锁、全局设置、渲染状态和降级状态。

禁止用多个 setTimeout 随意拼接复杂流程。优先使用明确阶段序列、Promise/async 时间轴、GSAP timeline 或可测试状态机。

所有位置、旋转、缩放、强度使用 lerp、damping、spring 或基于 deltaTime 的插值，避免直接跳值。快速连续点击不得造成重复提交、错乱回调或删除错误元素。

支持 prefers-reduced-motion。动画完成后清理临时节点、class、事件和锁定状态。
```

## 模块 07：DOM 与 WebGL 双层架构

### 适用

需要沉浸式效果，同时又要保持表单、文字、SEO、可访问性和产品可维护性。

### 提示词

```text
采用 DOM + WebGL 双层架构。

DOM 负责：语义文字、导航、按钮、表单、菜单、表格、焦点、键盘与可访问性。
WebGL/Canvas 负责：空间、情绪、复杂可视化、品牌主视觉和状态空间化。

推荐层级：
- z0：Three.js/Canvas；
- z1：暗角、雾、颗粒、扫描线；
- z2：正常页面内容；
- z3：Toast、命令面板、临时过渡对象。

WebGL 默认 pointer-events:none。只有明确需要拾取的对象使用 Raycaster，并为其提供 DOM 等价操作。

不要把整个 UI 画进 Canvas。保证即使 WebGL 不可用，核心内容与操作仍然存在。
```

---

## 模块 08：Three.js 高质感主视觉

### 适用

需要真正的空间主视觉，不满足于二维背景动画。

### 提示词

```text
为页面设计一个承担品牌与业务意义的 Three.js 主视觉。只保留一个中心母题，避免堆满无意义对象。

优先使用成熟组合：
- 一个主对象：实体材质 + 线框外壳 + 光晕层；
- 2 至 6 层具有不同轴向、速度和材质的辅助结构；
- 重复刻度、节点或碎片使用 InstancedMesh；
- 文本、图标或程序纹理使用 CanvasTexture；
- 大量点使用 BufferGeometry/Points；
- 关键形变使用 ShaderMaterial 与少量 Uniform；
- 高亮使用 Fresnel、局部自发光和克制 Bloom；
- 摄像机运动缓慢，交互对象运动更明确。

性能要求：
- DPR 桌面上限约 1.5-1.8，移动端约 1.1-1.35；
- 移动端降低粒子、细分、灯光和后处理；
- 动画循环内不创建新对象、不频繁查询 DOM；
- 页面不可见时暂停或降频；
- 无 WebGL 和依赖失败时有 Canvas/SVG/静态降级。

Three.js 必须由产品状态驱动。不要只做持续旋转的展示物。
```

---

## 模块 09：Shader 与材质强化

### 适用

模型形状普通，希望通过材质和光感提升质感。

### 提示词

```text
不要依赖增加模型数量来制造复杂度。通过材质层次、Shader 和光源建立体积感。

可使用：
- 顶点噪声或正弦扰动表现呼吸、能量、液体或生长；
- Fresnel 表现边缘光、半透明灵体和能量壳；
- 两到三种受控颜色混合；
- 局部纹路、扫描线、溶解阈值；
- 实体层 + 线框层 + Sprite 光晕；
- ACESFilmicToneMapping 与正确色彩空间；
- 少量雾和景深强化空间。

Uniform 必须映射到真实状态，例如 progress、power、error、success、voiceEnergy、scrollPhase。避免永远只按时间循环。

高亮区域保持有限。禁止满屏 Bloom、过曝白光、塑料感高反射和廉价赛博霓虹。
```

---

## 模块 10：跨媒介连续性

### 适用

希望输入、卡片、文本或按钮自然“进入”三维场景，而非突然切换。

### 提示词

```text
为 DOM 与 WebGL 之间建立知觉连续性。

当用户触发核心动作时：
1. 读取 DOM 对象的屏幕坐标；
2. 生成临时字符、碎片、光点或轮廓；
3. 沿可理解路径飞向 WebGL 主对象；
4. 在到达时触发空间对象汇聚、变形或点亮；
5. 清理临时 DOM；
6. 最终将空间结果收束回可操作的 DOM 工作区。

用户应感觉是“同一个东西发生转换”。不要同时播放两段互不相关的动画。

控制临时节点数量，动画结束后必须清理。支持快速重复操作与 reduced motion。
```

---

## 模块 11：微交互与操作手感

### 适用

页面整体不错，但按钮、输入、切换、加载和结果缺少精致反馈。

### 提示词

```text
对所有高频控件补齐完整状态：default、hover、active、focus-visible、disabled、loading、success、error。

反馈时长建议：
- 高频点击与按压：80-160ms；
- 状态切换：180-320ms；
- 结果结算：400-1200ms。

按钮点击不只换颜色，可以组合轻压、局部高光、边框收束或图标位移，但不造成布局跳动。输入框有明确焦点、错误和提交状态。Tabs 切换保持位置稳定。Toast 不遮挡关键操作。

所有反馈遵守统一运动语言和缓动曲线。不要每个组件发明一种动画。
```

---

## 模块 12：Web Audio 轻量声音系统

### 适用

需要提高仪式感、操作确认或阶段反馈，但没有专业音频素材。

### 提示词

```text
使用 Web Audio API 构建克制的程序化声音反馈。

要求：
- 用户首次点击后创建/恢复 AudioContext；
- 默认关闭或提供明显开关；
- 点击、选择、阶段推进、成功和失败使用不同频率、音色和包络；
- 使用 GainNode 设置快速起音和指数衰减，避免爆音；
- 限制并发和持续时间；
- 成功可使用短上行音程，失败使用低、短、克制音；
- 声音只做增强，不承担唯一信息；
- 页面隐藏、用户关闭或 reduced motion 时降低或停止。
```

## 模块 13：响应式与空间预算

### 适用

桌面端好看，手机、平板、矮屏或缩放后崩坏。

### 提示词

```text
不要按设备品牌写响应式。按内容空间定义 spacious、compact、portrait 和 scroll-safe 四种布局模式。

先计算：导航、标题、核心操作、主要内容、底部操作与安全间距的最低空间预算。

技术要求：
- Grid/Flex 承担主布局；
- minmax(0,1fr)、min-width:0、min-height:0；
- clamp、auto-fit、Container Query；
- 矮屏与窄屏分别处理；
- 触控目标不低于 40px；
- 手机重新安排视觉焦点与内容顺序；
- 复杂 WebGL 在手机减少粒子、细分和后处理；
- 不用整体 scale；
- 不用 overflow:hidden 掩盖核心溢出。

至少检查 390×844、640×360、768×1024、1366×768、1920×1080 和 125% 浏览器缩放。
```

## 模块 14：性能与资源治理

### 适用

页面动画多、移动端卡顿、GPU 占用高或首次加载慢。

### 提示词

```text
对当前页面进行性能治理，不牺牲核心视觉母题。

检查：
- JS 包体和外部资源；
- 图片、视频、字体、模型、纹理；
- Three.js Draw Call；
- 粒子数量和几何细分；
- DPR；
- 每帧对象创建与 DOM 查询；
- 不可见页面是否继续渲染；
- Resize/Scroll/Pointer 事件是否节流；
- 动画是否触发布局抖动；
- 低端移动设备降级。

优先措施：实例化、共享材质、纹理压缩、模型减面、按需加载、懒加载、暂停后台动画、降低 DPR、减少透明叠层、将复杂 DOM 动画改为 transform/opacity。

给出优化前后可观察指标。未实际测量时不要伪造 FPS、LCP 或体积数据。
```

---

## 模块 15：依赖失败与离线降级

### 适用

使用 Three.js CDN、外部字体、模型、图片、音频或 API。

### 提示词

```text
为所有外部依赖建立失败路径。

Three.js 或 WebGL 失败时，自动切换到 Canvas 2D、SVG、视频或静态主视觉。降级版本必须保留：品牌母题、核心状态、核心操作与结果反馈。

远程字体失败时使用经过校准的系统字体栈。图片/模型失败显示有设计的占位状态。API 超时提供重试、取消和明确错误信息。

页面不得因为单一资源失败而白屏。错误要写入开发日志，但不要把技术堆栈直接暴露给普通用户。
```

## 模块 16：工作台与管理后台审美升级

### 适用

后台、数据平台、编辑器、Agent 工作台、高密度工具页面。

### 提示词

```text
升级工作台与后台时，效率优先于艺术表演。

保留高信息密度、稳定位置、可预测操作和清晰状态。视觉强化集中在：层级、排版、焦点、选中、进度、错误、结果和关键数据，不在每个卡片上增加装饰。

要求：
- 主导航、二级导航和内容区权重明确；
- 高频操作固定且易到达；
- 表格、时间线、编辑器和 Inspector 保持稳定对比；
- loading、empty、error、permission、disabled、unsaved、saving、saved 状态完整；
- 危险操作有确认与恢复；
- 键盘操作和 focus-visible 可用；
- 艺术化场景只用于入口、空状态、结果或低频仪式，不干扰日常生产。
```

## 模块 17：内容站与品牌官网升级

### 适用

个人网站、知识库、作品集、付费内容站、品牌官网。

### 提示词

```text
采用“统一策展外壳 + 局部项目个性”的结构。

统一：字体尺度、边距、项目编号、标签、进入/退出转场、阅读宽度、页脚和导航。
局部：每个项目或专题可以拥有独立主色、图像、动态封面和情绪母题。

首页先建立品牌世界，再进入内容；正文阅读区保持稳定、清楚、低干扰。动态封面与视觉奇观集中在入口和章节过渡，不能污染长文阅读。

```

## 模块 18：浏览器验收与防假完成

### 适用

任何 Agent 完成开发后。

### 提示词

```text
不要只看源码。启动项目并用真实浏览器完成定向验收。

至少测试：
1. 首次进入；
2. 核心成功路径；
3. 输入为空或错误路径；
4. 快速重复点击；
5. 完成后再次执行；
6. 桌面和手机；
7. 一个矮屏；
8. 键盘焦点；
9. prefers-reduced-motion；
10. 外部资源失败；
11. 控制台和网络错误；
12. scrollWidth <= clientWidth。

所有结论标记为 observed、reproduced、inferred、existing、regression 或 fixed_verified。

只有实际复测通过，才能写“已修复”。浏览器不可用时，明确写“未进行真实浏览器验收”，不要用静态代码检查冒充实测。
```

```text
- 对齐与间距；
- 边框与明暗权重；

- Toast、Modal、Tooltip；
- 资源失败和重复点击。

```

# 第五部分：按模型能力拆分的执行轮次

## 5.1 强 Agent：一轮执行

适用于能读仓库、运行项目、修改代码、截图和测试的 Agent。

```text
执行完整总控提示词。先审计与冻结，再设计、实现和验证。不要在没有运行项目之前直接大规模重构。
```

## 5.2 中等 Agent：四轮执行

### 第一轮：只审计

```text
读取项目并运行。输出项目地图、核心路径、must_keep、do_not_touch、当前视觉问题、响应式问题和最高收益升级点。不要修改代码。
```

### 第二轮：只建立视觉系统与示范页

```text
基于上一轮审计，为项目建立视觉命题、Design Token 和一个核心页面示范。保留业务逻辑，只修改共享样式、组件表现和该页面布局。完成后运行并截图检查。
```

### 第三轮：只加入动效/空间层

```text
在示范页中加入与业务状态绑定的语义动效。必要时采用 DOM + WebGL 双层结构。不得修改其他页面和业务。完成成功、失败、重复执行和降级路径。
```

### 第四轮：扩展与验收

```text
将验证过的 Token、组件与动效规则扩展到相邻页面，处理手机、矮屏、性能和资源失败，并做浏览器回归。只修实测发现的问题。
```

## 5.3 弱模型：六轮小任务

1. 只识别页面结构和核心功能；
2. 只修改色彩、字体、层级和留白；
3. 只统一按钮、输入和卡片状态；
4. 只增加一个主视觉；
5. 只处理手机布局；
6. 只修浏览器实测问题。

每轮都追加：

```text
保留上一轮已经可用的功能与视觉。只处理本轮指定范围。不要重新生成整个页面。
```

# 第六部分：压缩版提示词

## 6.1 约 500 字极速版

```text
在不破坏现有业务、路由、数据、API、鉴权和状态的前提下，升级当前项目的前端视觉与交互。先运行项目并列出 must_keep、do_not_touch 和本轮范围，禁止推倒重做。

先定义一句视觉命题：“情绪 + 材质 + 核心形状 + 动态特征 + 克制原则”，再建立统一 Design Token。避免紫蓝渐变、满屏玻璃卡、同尺寸圆角矩形、无意义光球粒子和低对比灰字。页面只保留一个主焦点、一个动效语言和两级强调色。

动画必须解释真实状态。建立业务状态、动画状态、异步锁、用户设置和降级状态；处理空闲、输入、加载、成功、失败、结果和重复执行。需要 Three.js 时，DOM 负责文字与操作，WebGL 负责空间与情绪；重复物体实例化，限制 DPR，移动端减粒子，支持 reduced-motion，并准备 Canvas/SVG 降级。

手机端重新组织布局，不整体缩小。完成后实际浏览器测试核心成功/失败路径、快速重复点击、390×844、1366×768、矮屏、键盘焦点、外部资源失败、控制台错误和横向溢出。未实测内容必须标记未验证。
```

## 6.2 约 1000 字通用升级版

```text
你负责对当前项目执行非破坏式前端升级。先读取真实代码、路由、组件、状态、API、数据与构建方式，并运行现有项目建立基线。保留数据库、鉴权、权限、路由、核心业务状态和用户未提交文件。先输出 must_keep、do_not_touch、修改范围、风险和验收标准。

不要直接换色或堆特效。先写出视觉命题：“情绪 + 材质/媒介 + 核心形状 + 动态特征 + 克制原则”。将“高级、炫酷、科技、东方”等词转成具体色彩比例、留白、形状、光源、材质与速度。页面只能有一个主视觉焦点、一个主要动效语言和两级强调色。消除紫蓝渐变、满屏玻璃拟态、同尺寸圆角卡片、无业务意义粒子、过度辉光和低对比灰字。

建立语义 Design Token，统一颜色、表面、文字、边框、间距、字号、圆角、阴影、z-index、动画时长与缓动。通过明暗、排版、留白和运动速度建立信息层级，关闭背景动效后页面仍应成立。

先列出产品空闲、输入、处理、等待、成功、失败、结果可编辑和重试状态，再将状态映射为视觉参数。动画必须有来源和去向，使用 lerp/damping/deltaTime，处理重复点击和异步锁。若使用 Three.js，采用 DOM + WebGL 双层架构：DOM 负责文字、表单与可访问性，WebGL 负责空间与品牌。控制 DPR、Draw Call、粒子、透明层和移动端负载；外部资源失败时切换 Canvas/SVG/静态场景，禁止白屏。

响应式按 spacious、compact、portrait、scroll-safe 重排，使用 Grid/Flex、minmax(0,1fr)、min-width:0、clamp 和安全滚动，不整体 scale，不用 overflow:hidden 掩盖问题。

完成后真实浏览器测试首次进入、成功、失败、快速点击、再次执行、手机、桌面、矮屏、键盘焦点、reduced-motion、资源失败、控制台错误与横向溢出。只把实际复测通过的项写成 fixed_verified。
```

# 第七部分：针对不同项目类型的附加指令

## 7.1 SaaS / AI 工具

```text
让真实产品组件承担主叙事。首屏可以演示一次真实工作流，而非放与产品无关的宇宙或机器人。把输入、分析、生成、结果和继续编辑做成可感知的状态序列。产品界面优先清晰、速度与可信度。
```

## 7.2 编辑器 / 视频工具

```text
时间线、素材区、预览区、Inspector 和导出状态必须稳定。视觉奇观只用于入口、语义分析、结果结晶或关键转场；完成后收束到可编辑工程。强调可逆、可替换、可追踪和可继续修改。
```

## 7.3 管理后台

```text
后台不追求沉浸式。提高表格、筛选、批量操作、状态、权限、错误恢复和信息密度。允许入口或空状态有品牌视觉，其余页面保持高效率和低干扰。
```

## 7.4 个人 IP / 品牌官网

```text
先建立一个可被记住的视觉母题，再用统一策展外壳组织不同项目。IP 语言通过材质、光源、形状、文案节奏和转场体现，不依赖装饰性符号堆砌。
```

## 7.5 儿童或轻游戏

```text
提高点击目标、反馈清晰度和成功感。动效更有弹性，但保持一个统一运动语言。声音短、轻、可关闭。避免低对比、复杂菜单、过长说明和容易误触的细小控件。
```

# 第八部分：自检与验收清单

## 8.1 视觉

- [ ] 一眼能识别页面主角；
- [ ] 主操作明显；
- [ ] 色彩不超过必要数量；
- [ ] 关闭动效后仍有设计；
- [ ] 缩略图下层级成立；
- [ ] 没有明显通用 AI 模板感；
- [ ] 装饰都服务情绪或操作；
- [ ] 前台与后台采用不同密度策略。

## 8.2 交互

- [ ] hover、active、focus、disabled、loading 完整；
- [ ] 动画有来源和去向；
- [ ] 加载期间防重复提交；
- [ ] 成功、失败、空状态、撤回和重试完整；
- [ ] Toast/Modal 不遮挡关键操作；
- [ ] 键盘可达；
- [ ] 声音可关闭。

## 8.3 Three.js / Canvas

- [ ] 3D 对象映射真实产品概念；
- [ ] DPR 有上限；
- [ ] 重复物体实例化；
- [ ] 移动端降级；
- [ ] 页面隐藏时降频；
- [ ] 不可用时有替代场景；
- [ ] 没有无意义满屏 Bloom；
- [ ] 动画循环不持续创建对象。

## 8.4 响应式

- [ ] 390×844 可用；
- [ ] 640×360 不被顶部/底部挤死；
- [ ] 平板有合理布局；
- [ ] 宽屏没有大面积浪费；
- [ ] scrollWidth <= clientWidth；
- [ ] 触控目标足够大；
- [ ] 没有整体 scale；
- [ ] 核心内容未被 overflow 隐藏。

## 8.5 工程

- [ ] 没有破坏路由/API/鉴权；
- [ ] 没有覆盖未提交文件；
- [ ] 控制台无新增错误；
- [ ] 外部资源失败不白屏；
- [ ] 未实测内容明确标记；
- [ ] commit、push、PR、CI、部署状态分别说明。

```text
    └── build-handoff.py
```

## Skill 的建议触发范围

未来 Skill 可以在用户提出以下请求时触发：

- 提升前端审美；
- 已有网站升级；
- 不要模板感；
- 加强交互和动效；
- 加入 Three.js 但不要廉价；
- 将产品状态空间化；
- 修复移动端拥挤、错位、溢出；
- 做成可正式交付产品；
- 浏览器实测并回归；
- 只做增量精修，不改坏功能。

## Skill 的核心判词

> **不以特效数量衡量高级，不以截图美观代替产品成立。先把产品状态、品牌母题和用户动作建立因果，再用前端技术把这条因果变成可见、可感、可操作的体验。**

---

# 第十一部分：最重要的五条原则

1. **先保护业务，再升级视觉。**
2. **先定义产品状态如何空间化，再决定 Three.js 画什么。**
3. **一个强母题，胜过十种无意义特效。**
4. **DOM 负责可靠操作，WebGL 负责空间与情绪。**
5. **实际浏览器验证，胜过任何“看起来应该没问题”。**
