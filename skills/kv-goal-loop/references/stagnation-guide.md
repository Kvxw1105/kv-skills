# 停滞检测与迭代决策快速参考

## 停滞检测

| 连续失败次数 | 动作 |
|------------|------|
| 1 | 根据评估反馈调整方案，继续 |
| 2 | 强制切换方法（换算法/架构/工具链） |
| 3 | 暂停循环，请求用户介入 |
| 5 | 强制退出，输出最佳尝试 |

## 停滞诊断问题

当连续失败 ≥ 2 时，回答：

1. 最近 3 次的失败原因是同一个根因吗？
   - 是 → 必须切换方法
   - 否 → 每次都是新发现，继续当前方法
2. 验证失败是因为代码错误还是标准定义过严？
   - 代码错误 → 修复代码
   - 标准过严 → 可能需要与用户协商调整标准
3. 有没有外部依赖阻塞？
   - 有 → 解决依赖或绕过
   - 没有 → 纯粹是方案问题，换方案

## 迭代决策树

```
验证 PASS + 评估 PASS → ✅ 完成
验证 PASS + 评估 FAIL → 🔄 根据反馈调整
验证 FAIL + 新错误 → 🔄 修复错误
验证 FAIL + 重复错误 → ⚠️ 切换方法
切换方法后仍 FAIL → 🛑 请求用户介入
达到 max_rounds → 🛑 强制退出 + 输出最佳尝试
```

## 方法切换策略

当需要"切换方法"时，按以下优先级尝试：

1. **换算法**：同样的架构，换具体实现
2. **换工具链**：换依赖库、换框架、换构建工具
3. **换架构**：重新设计整体方案
4. **降级目标**：先实现核心功能，再迭代增强
5. **求助**：向用户请求更多信息或指导
