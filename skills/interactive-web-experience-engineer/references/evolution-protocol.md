# 经验进化协议

每次实战后检查是否出现：

- 真实复现的新 Bug 或平台限制；
- 被用户明确认可或否定的视觉、交互、音效和工程规则；
- 跨项目可复用的提示词结构、测试方式或代码模式；
- 原有规则被证伪或需要替代。

候选必须同时满足：新颖、可复用、可行动，并且有实际任务证据。一次性情绪、隐私、未经验证传闻和只对单个页面有效的魔法数字不得沉淀。

存在高价值候选时，在任务末尾询问：

```markdown
### 可沉淀的新经验
- 候选：...
- 证据：...
- 适用范围：...
- 建议写入：...

是否把它沉淀进工程 Skill？
```

获得明确同意后更新对应 reference；记录日期、来源任务、替代关系和验证状态。Skill 环境只读时生成结构化补丁，不能声称已永久更新。
