# 实现架构

## 选择技术栈

优先原生 HTML/CSS/JavaScript，适合单页小游戏、闪应用和快速验证。以下情况再考虑框架：

- 多页面和复杂路由；
- 大量可复用组件；
- 复杂异步数据和协作；
- 已有项目明确使用 React/Vue 等。

不要为简单互动页引入重型依赖。

## 状态分离

至少区分：

- 业务内容和当前关卡；
- 用户输入；
- 系统提示或锁定内容；
- 成功、失败和结算；
- 动画临时状态；
- 设置，如主题、声音、大小写；
- 持久化数据，如本地最佳。

删除、撤回和动画回调使用稳定 ID，不只使用易变化的数组下标。

## DOM 与组件结构

每个区域只承担一种职责：

- shell：视口和主题；
- header：品牌与设置；
- primary：核心动作；
- secondary：进度和说明；
- actions：提示、提交、重置；
- result：结算和分享。

## 资源和安全

- 不在前端写密钥。
- 远程资源必须有失败回退。
- 音频、字体和图片记录来源。
- 用户输入进行基本转义。
- 本地存储使用版本化 key。

## 修改现有项目

1. 先识别核心 DOM、状态和事件。
2. 保存可工作的版本。
3. 先修结构，再修组件，再修装饰。
4. 一次只改变一个层级。
5. 每轮复测核心路径。
6. 不为修 CSS 重写无关业务逻辑。
