# 交付质量检查

## 产品

- 用户进入后知道产品是什么、下一步做什么。
- 核心任务可在合理步骤内完成。
- 无空按钮、死链接、假数据结论或无解释的失败。
- 心理、医疗、财务等高风险主题有清楚的非诊断或非专业替代说明。

## 视觉

- 主体与主标题优先级明确。
- 正文、占位符、禁用状态均可读。
- 深色模式不是灰字叠黑底；浅色模式不是灰字叠灰白。
- 毛玻璃只用于适合悬浮的控制层，长文本和密集表格使用稳定实体表面。
- 圆角有层级，不是全站同一大圆角。

## 交互

- Hover、Focus、Active、Disabled 状态明确。
- 加载、成功、失败、空状态完整。
- 主题切换、返回、重置和再次开始可用。
- 动效不会阻塞点击或隐藏内容。

## 工程

- TypeScript、构建和静态检查通过。
- 构建产物不依赖 localhost。
- 单文件中无未解析的本地 JS/CSS 路径。
- localStorage 使用容错处理。
- Three.js 资源和事件监听被清理。
- 移动端没有横向溢出和不可点击的小控件。

## 最终回复

- 第一项是可直接点击的预览 HTML。
- 其次才是源码 ZIP、构建 ZIP 和设计文档。
- 对模拟后端、离线限制和未实现能力如实说明。
