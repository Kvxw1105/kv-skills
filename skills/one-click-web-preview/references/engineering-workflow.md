# 工程工作流

## 1. 需求转译

先提炼四项：

- 用户最终要完成的任务。
- 最短可用路径。
- 必须真实实现的功能。
- 可在预览阶段模拟的外部能力。

技术栈由任务复杂度决定：

- 展示、表单、小游戏、小测试：原生 HTML/CSS/JS 足够时不要上重框架。
- 多页面状态、复杂组件、可持续迭代：React + TypeScript + Vite。
- 三维空间、数据关系、沉浸视觉：Three.js / React Three Fiber，但需要静态降级。

## 2. 先设计后开发

编码前输出或内部形成：

1. 核心用户路径。
2. 页面和路由结构。
3. 组件层级。
4. 正常、空、加载、错误、完成状态。
5. 桌面、平板、手机布局。
6. 深色、浅色主题变量。
7. 动效与性能预算。

避免只设计首页。功能型应用要覆盖进入、操作、结果、历史或重置。

## 3. 实现优先级

按顺序完成：

1. 核心流程可运行。
2. 数据和状态正确。
3. 响应式与主题。
4. 视觉材质和动效。
5. Three.js 与高级效果。
6. 分享、导出、快捷键等增强能力。

高级视觉不能建立在失效按钮、不可读文字或断裂流程之上。

## 4. Three.js 使用

适合：

- 作为低强度环境层。
- 表达数据关系、知识图谱、工作流或真实三维对象。
- 在欢迎、运行、结果等关键状态增强情绪。

要求：

- 限制 devicePixelRatio。
- 页面隐藏时暂停。
- 移动端降低几何体、粒子和后处理。
- 支持 prefers-reduced-motion。
- WebGL 失败时保留 CSS/SVG 静态背景。

## 5. 测试

至少检查：

- 首次进入和刷新恢复。
- 所有主按钮。
- 键盘和鼠标交互。
- 手机宽度 360–430px。
- 深色与浅色模式。
- 最终结果、重置和再次使用。
- 构建后的页面，而不只检查开发服务器。
