# 网页一键预览

把用户的网页需求转化为可用产品，并把“点开就能看”作为首要交付标准。先设计，再开发，再验证，最后交付直接预览入口。

## 工作原则

- 只围绕用户目标做技术决策，不要求用户替你选框架、构建工具或部署方式。
- 除非存在会改变产品方向的关键歧义，否则直接推进，不向技术小白抛出工程问题。
- 视觉风格与工程交付分离：用户指定其他风格 Skill 时，先遵循其视觉系统，再用本 Skill 完成应用逻辑、测试和一键预览。
- 不把静态截图冒充网页预览；交付必须包含真实可交互页面。
- 不让用户默认执行命令、安装 Node.js、配置服务器或阅读长篇部署教程。

## 决策流程

1. 判断任务类型：
   - 新建简单网页：优先单文件 HTML/CSS/JS。
   - 新建复杂应用：优先 React + TypeScript + Vite；需要空间交互时使用 Three.js 或 React Three Fiber。
   - 修改现有项目：沿用现有技术栈，不为追求形式强行重构。
2. 判断运行依赖：
   - 纯前端：必须生成可直接打开的单文件预览。
   - 依赖后端、账号、数据库或私密 API：为预览提供高保真本地模拟数据；清楚标注哪些能力尚未连接真实服务。
3. 判断产品结构：
   - 官网、专题页可采用滚动叙事。
   - 工具或应用必须设计进入逻辑、导航、工作区、任务状态和结果路径，不得一律做成长滚动页面。
4. 先形成简洁设计方案，再编码。设计至少覆盖：核心用户路径、页面结构、关键状态、响应式、深浅模式与视觉层级。

## 开发要求

- 实现真实交互，不留下“后续自行实现”、空按钮或伪功能。
- 对复杂应用至少处理：首次进入、正常状态、加载、空状态、错误、完成结果。
- 默认支持桌面和手机；移动端重新组织布局，不能只缩小桌面页面。
- 用户提出深浅模式时，使用语义化 Design Token，避免简单反色。
- Three.js 必须服务于空间、情绪或功能，不使用无意义的发光球、粒子宇宙或持续高负载动画。
- 玻璃材质、圆角、阴影和边框按层级使用，核心阅读与编辑区域保持稳定对比。
- 需要本地进度时优先使用 localStorage，并提供重置机制。
- 兼顾键盘操作、焦点状态、可读对比和 prefers-reduced-motion。

详细工程策略见 [references/engineering-workflow.md](references/engineering-workflow.md)。

## 一键预览交付

把直接预览文件作为第一交付物，文件名优先使用中文主题名，例如 `心理年龄测试-直接预览.html`。

### 简单网页

直接生成自包含 HTML：

- CSS 写入 `<style>`。
- JavaScript 写入 `<script>` 或无外部依赖的内联模块。
- 图片、字体与必要资源使用 data URI、内联 SVG 或程序化绘制。
- 不依赖 CDN；离线打开仍应运行。

### React / Vite / Three.js 项目

1. 配置构建为单入口、单 JavaScript 包、单 CSS 包，并尽量内联静态资源。
2. 执行正式构建。
3. 使用 `scripts/make_single_html.py` 把构建产物转为单文件 HTML。
4. 使用 `scripts/check_single_html.py` 检查残留外部本地资源引用。
5. 在浏览器或可用的自动化环境中验证首页、主要流程、主题切换和结果页面。

具体构建配置见 [references/preview-packaging.md](references/preview-packaging.md)。

### 交付顺序

最终回复按以下顺序：

1. 第一行给出“一键预览”链接。
2. 用一句话说明打开后能做什么。
3. 再提供源码包和构建包；只有用户需要继续开发时才解释这些文件。
4. 若存在后端模拟或浏览器限制，简短说明，不把限制藏起来。

不要把压缩包放在预览链接前面。不要让用户先下载开发工具。

## 质量门槛

交付前执行 [references/quality-checklist.md](references/quality-checklist.md) 中的检查。至少确保：

- 构建和类型检查通过。
- 页面打开无白屏、无明显控制台错误。
- 主要按钮和完整核心流程可用。
- 字体、背景和控件对比清楚。
- 深浅模式均检查关键页面。
- 手机宽度下无严重溢出。
- 单文件预览不引用本机绝对路径、`localhost`、未打包的 `/assets/` 文件或仅开发环境可用的 API。

## 中文自然语言触发示例

- “直接在你这里把网页做出来让我预览。”
- “做个 React 网页，给我一个点开就能用的链接。”
- “我不懂技术，不要让我配环境，直接一键打开。”
- “先把交互设计好，再开发成能预览的网页。”
- “把这个 Three.js 项目打包成单文件预览。”
- “帮我把现有网页改完并直接给我看效果。”
- “用答案之外风格做一个工具网页，完成后让我直接点开。”
